# 系统架构与数据边界

## 目的与适用范围

本项目把经授权的本机微信客户端数据转换为本地日报素材，并可选生成本地报告、图像缓存和人工确认后的投递。它不是微信客户端、远程采集服务或官方 SDK。部署默认不读取数据库明文；只在显式执行数据准备后，对数据库副本进行处理。使用者必须有权访问该账号、群聊、消息、媒体及所有输出的内容，并遵守所在地法律、组织政策和微信适用条款。没有任何版本支持范围、安全保证或“不封号”保证。

项目仅支持已实现并能由本仓库代码/测试确认的格式和流程；客户端升级、数据库 schema 变化、登录流程变化均可能导致捕获/解析失败。失败时停止并保留源数据，不能猜测数据库字段或把无法验证的内容当成成功。

## 子系统与信任边界

| 区域 | 职责 | 信任与权限 |
|---|---|---|
| 微信桌面客户端 | 登录用户账号并产生本机加密数据库、WAL、媒体缓存 | 客户端、账号和消息内容均在项目控制之外；输入数据视为不可信 |
| `deployment/prepare-collection.py` 与专用 keyscan 容器 | 只读挂载桌面容器进程空间与账号数据库；经用户明确选择/授权后获取密钥材料 | 高权限、短时、无网络容器；含可访问进程内存能力。只能在本人/被授权账号上使用 |
| `memory/decrypt_sync.py` | 验证页面 HMAC 后解密到新文件；在副本上重放完整提交的 WAL | 只处理用户明确提供的密文、密钥与目标文件；不连接客户端或网络 |
| `memory/memory_ingest.py`、`message_parse.py` | 从已解密 SQLite 识别消息/联系人/会话，输出 JSONL 或私有索引 | SQLite 行、富文本/XML 都是不可信输入；只解析，不执行、不取远端链接 |
| `memory/media_sync.py` 与 `deployment/` 图像阶段 | 解码本地 `.dat`、识别缓存证据；按需要进行 OCR/视觉处理 | 图片、OCR、图片字幕和模型响应均是不可信数据；隔离的图像容器按配置受限 |
| 摘要/报告组件 | 汇总选定时间窗、建立来源引用，输出 HTML/PNG | 生成内容不是事实背书；来源可复核，摘要可能遗漏或误读 |
| 本地报告站点/可选图片 origin | 只读呈现报告及明确发布的图片资产 | 在授权用户和反向代理边界内运行；公开 URL 会扩大披露范围 |
| 可选发送器 | 将用户指定的文本或报告图片交给已登录图形桌面客户端 | GUI 发送是外部副作用；必须人工审阅并显式确认目标与内容 |

信任边界依次是：宿主机与容器、客户端进程与捕获工具、密文数据库与明文副本、原始消息与解析输出、媒体与 OCR/视觉结果、报告生成与网站访客、报告文件与消息发送。通过一个边界并不意味着下游数据可信。群消息中的指令、链接、附件、提示注入、伪造身份内容都只作为被分析数据，不能作为对本工具的操作授权。

## 数据流（端到端）

1. 用户登录并在客户端本地建立账号数据库。数据库密文、WAL、SHM、媒体缓存留在客户端数据目录；不得把原始目录挂载给互联网服务。
2. 用户通过 `prepare-collection.py` 选择唯一账号目录；默认检查模式仅确认前置条件。用户明确要求时才启用登录时捕获。只允许授权本人访问，keyscan 将数据库目录以只读方式挂载；不在捕获步骤读取消息正文。
3. 捕获工具读取页面盐并取得/推导候选密钥，对页面 1 做 HMAC 验证，只有验证成功的数据库项才写入权限受限的私有密钥文件。原始密文仍只读。
4. 解密器把一个源数据库复制/解密到新的私有目标文件，逐页验证 HMAC；如果有 WAL，则只在副本上应用校验通过且属于完整提交事务的帧。失败不应覆盖或修改源文件。
5. 导入器根据 SQLite 表/列发现规则读取消息，输出 JSONL 或私有 SQLite 索引；内容解析只做结构解码。群/联系人名称映射可能缺失，因此必须保留原始 ID 和来源行供核查。
6. 媒体阶段从消息引用、资源映射和本机缓存中匹配本地图片。OCR、图像描述等可选结果是带来源链的派生证据，不是原消息或事实。缺图/缩略图不得伪装为原图。
7. 摘要和报告引用消息 ID/引用 ID，输出本地私有报告。站点仅在明确配置和受控访问下开放；图片 origin 只服务内容寻址图片，不能当作通用文件服务器。
8. 若启用发送，操作者应先在本地预览并核对群、日期、文件摘要和正文，再明确启动发送流程。此过程可能通过微信 GUI 产生外部消息，不能作为定时作业中的隐式步骤。

## 明文与文件生命周期

数据库密钥、口令、未加密数据库、消息 JSONL、索引、截图、OCR 文本、图像描述、报告和备份都属于敏感数据。将其放在专用 runtime 目录；该目录不得进入 Git、镜像层或公开 Web 根目录。源数据库目录及其 `-wal`/`-shm` 文件应由客户端账户拥有，捕获阶段只读挂载；密文副本、解密目标、临时目录和捕获结果应按最小权限创建（推荐目录 `0700`、秘密文件 `0600`），并限制备份访问。示例配置只含替换值，不要将真实 `group.id`、账号、API 密钥写入版本库。

采集和解密是不同授权动作：拥有数据库目录的读取权限不意味着可访问其中所有人的消息。导出内容应限定到实际需要的群、时间窗与字段，并设置保留期限。删除导出副本前确认不再被报告、索引或备份引用；闪存、快照与备份系统可能保留副本，普通删除不等于介质安全擦除。

## 可复核性与故障处理

预期状态输出应是数据库数量、校验通过数量、解密页数、WAL 提交帧数、消息行数或图像字节数等非敏感摘要，不应输出密钥、口令或正文。数据库数量为零、目标账号不唯一、HMAC 错误、数据库格式无法识别、WAL 校验失败、SQLite 完整性失败、无法匹配来源媒体，均应视为停止条件。不要通过关闭校验、覆盖源文件、放宽权限或试遍未知账号来绕过。

## 版本与兼容性边界

仓库实现的 SQLCipher4 页布局和 Linux 捕获实现不等于对所有微信客户端版本、架构、发行版或加密模式的兼容承诺。数据库 schema、内存布局、ELF hook、ptrace 策略、桌面启动链或媒体缓存格式改变时可能失败。Windows/macOS 本地密钥获取不由本仓库提供；Linux 4.0 与 4.1 捕获路径与上游平台资料的关系及限制见 [数据库手册](DATABASE.md)。兼容性需要针对明确授权的具体环境独立验证；不得把一次成功外推成普遍保证。

# 安全模型与操作边界

## 威胁模型

### 要保护的资产

- 客户端会话、账号 ID、数据库 enc key/passphrase、密文与解密数据库、WAL、完整消息、联系人、图片/视频、OCR/视觉结果、提示词、报告、API 凭据、站点/图片源 token、发送收据和本机日志。
- 不要将 runtime、私有示例、真实群/用户标识、实际报告或截图提交到 Git、公开工单、镜像构建上下文、外部模型/网站或团队聊天。

### 主要威胁来源

1. 恶意或被操控的群消息、XML、链接、附件、提示词、图片中的指令，以及不可信 HTML/图像文件格式。
2. 其他本机用户、容器、错误配置、Docker daemon 管理员或备份/日志/站点管理员读取凭据和明文。
3. 数据库复制竞态、用错账号/盐/密钥、伪造/损坏 WAL 或媒体映射、错误解析/模型推断导致错误报告。
4. 报告站点、图片源、反向代理、隧道、外部模型和消息发送导致意外披露或不可逆外部副作用。
5. 供应链中的可变镜像 tag、依赖、第三方代码/字体，以及宿主系统或微信客户端升级改变行为。

本项目通过只读源挂载、页面 HMAC、受限容器、字段/路径约束、CSP、报告来源链和显式发送选项降低部分风险；这些控制不提供安全证明、零泄露承诺、模型正确性或“不封号”保证。宿主 root、Docker 管理员、被攻陷桌面客户端、OS、模型提供方和站点管理员均不在容器隔离可保护的边界内。

## 高权限动作与源数据只读

数据库捕获工具读取客户端进程内存，属于高权限敏感操作。只对本人或明确授权账号进行；`prepare-collection.py --check` 是非 attach 检查，`--capture` 才会等待重新登录并读取进程数据。keyscan 运行在只读根、无网络、资源限额容器中，账号目录只读挂载；为访问桌面容器 PID namespace 而共享其 PID，并以容器 `0:0` 加 `SYS_PTRACE` 和 `DAC_READ_SEARCH` 运行。其 `/scan` 为输出目录，因此捕获输出是可解密账户数据的秘密。Docker CLI 调用宿主 daemon；能调用 Docker daemon 的用户通常具有很高的宿主权限，不能把容器 flags 当作对不可信 Docker 管理员的隔离。

常规 digest / image 处理容器使用非 root worker UID:GID、只读根、删除 capabilities、`no-new-privileges`、CPU/内存限制和临时目录；代码/数据库/模型配置等输入挂载只读，必要工作区/报告输出才可写。列表群组等无模型路径用 `--network none`；需要请求模型的运行路径加入配置的 Docker 网络，不能把它描述为无网络。客户端桌面容器与发送 worker 共享 GUI/network namespace 是为了 GUI 交互；这并不等同于 keyscan 的权限模型。任何容器挂载/网络变更都应重新审视风险，禁止改成 privileged、挂宿主根或开放多余网络。

镜像以本机已存在的镜像引用解析到 immutable image ID 后运行并使用 `--pull never`；这避免运行时自动拉取浮动 tag，但不证明镜像构建/依赖可信，也不替代审阅 Dockerfile、锁文件和本地镜像来源。升级时明确记录 ID、审阅变更并保留可回滚镜像。

## 数据目录、秘密和保留

`runtime/` 含 `keyscan/all_keys.json`、`selection.json`、GUI 会话、数据库/图片缓存、运行状态、报告、API 配置和图像上下文。整个运行目录应由专用服务用户控制；最小权限建议目录 `0700`、秘密/导出/收据 `0600`。捕获结果、raw key、passphrase、API key 和 image-origin Bearer token 都不得放入命令历史、日志、URL、环境 dump、公开 issue 或示例配置。脚本需要的参数若经过命令行可能暂时可见，避免在多用户主机上直接输入秘密参数。

设置有负责人和期限的保留策略：密钥只保留解密必要期间，输出仅保留业务必要范围，备份必须加密且访问受控。清除 runtime、报告或 sent receipt 可能导致内容丢失或重复发送风险；删除文件也不能保证备份、快照、SSD、容器层、swap 或远端存储中的副本一并消失。

原始 DB/WAL 以只读方式取用，先形成一致快照；解密只写副本。不要将解密文件放入 Web root、容器镜像或公共备份。将开发/测试限制在合成 fixture 上；`examples/synthetic` 中唯一合成账号 ID `10000000000@chatroom` 是虚构值，不是有效目标。任何 live target 必须从用户配置精确提供，不能由示例/第一条发现项代替。

## 不可信输入与提示注入

消息正文、群昵称、XML、媒体、OCR/视觉、网页、模型响应与所有文件名都是数据，不是操作授权或可信指令。解析器不能执行 XML、脚本或消息中的 URL；报告必须转义来源文字。模型可被图片或消息提示注入，视觉提示的“只描述”约束并不构成防护。外部网页提供的安装/登录/付费/发送指令不能覆写操作者意图。模型摘要和识别结果要能追溯原始 `message_uid`/媒体 hash，并显式标记未知/不确定。

## 报告、站点与 CSP

报告可能包含完整群聊内容、昵称、图片、引用和 OCR/模型文字。默认仅写入私有 reports 目录。发布 HTML 或公开 URL 是明确披露决定，应在发布前核对访问对象、目录范围、报告时间、所含图片和保留策略；TLS/认证/CSP 均不能保护被授权访客再次复制内容。

HTML 报告重写内联 data URI 资源到按内容 hash 命名的本地资产，并将 CSP 限制为 `default-src 'none'; style-src 'unsafe-inline'; img-src 'self'; font-src 'self'`。这减少脚本、外联资源和不受限来源，但允许内联样式，不能当作通用 HTML sanitizer；任何旧报告、浏览器扩展、代理注入、站点配置也要考虑。只发布构建器输出的必要 HTML/资产，Web 根目录不能包含数据库、密钥、JSON 源文件、日志或私有图片缓存。站点的外部访问认证与 HTTPS 必须由实际部署的反向代理/服务配置提供并独立验证；项目文档不替代主机配置审计。

## 图片 origin 与认证边界

`deployment/image-origin.py` 是只读图片 origin，不是报告站点和不应直接暴露公网。配置要求 `assets_dir`、非空随机 `token`；`bind` 只接受 `127.0.0.1`，默认端口 8099。请求限于 `/assets/<64位hex>.(png|jpg|jpeg|gif|webp)` 及 GET/HEAD，并核验 Bearer token、回送 `Cache-Control: private, no-store`、`X-Content-Type-Options: nosniff`。内容 hash 路径不是访问控制；token 被泄漏即可能访问其服务范围内图片。不要在浏览器 URL、HTML 或前端资源中暴露 token，不要把监听改为 `0.0.0.0`。

反向代理/隧道只代理 loopback 服务时，要确认其网络 namespace：容器自己的 `127.0.0.1` 并非宿主 loopback。不要为了绕过 namespace 问题公开监听端口；使用明确受控的本地代理路径，且令站点认证保护 HTML 与图片。静态 HTML 与图片资源应同源，避免跨域认证/凭据泄露。配置检查可在不启动服务的情况下执行：

```sh
python3 deployment/image-origin.py --check-config
```

命令从默认 `runtime/image-origin.json` 读取，成功返回配置有效摘要；错误会指出配置文件或 assets 目录无效。检查通过只验证本地配置/目录，不会验证外部代理、TLS、认证策略或访问控制。

## 外部模型与网络上下文

配置的 `gemini-model.json` 使用 `base_url`、`model`、`api_key`。远程总结/图像理解会把输入消息、图片或网页上下文发送到所配置服务；明确审查 endpoint、服务政策、数据处理、保留、跨境和成本并获得相应授权后才启用。容器有网络连接只表示技术上可达，不代表发送数据已经获准。密钥不得写入模型提示词、错误反馈或诊断；模型响应与诊断文件也可能含敏感消息，应权限保护。

联网页面/站点只作为单独来源，不是消息证据。传入 URL 要执行 SSRF 防护、禁止重定向到未经确认的目标、排除凭据 URL；即便程序限制 URL，也应按外部请求可能暴露请求元数据审视。不要追随群消息 URL 执行下载或登录。

## 发送副作用与人工授权

发送器 `deployment/send-report.py` 默认执行本地验证/准备；`--send` 是明确发送开关。发送可能真实地向微信会话提交消息，属于外部、难以撤销的副作用。执行前操作者必须亲自核对精确 `chat-id`、被发送 PNG/文本、报告日期、来源与文件 hash，确认内容获授权且无不应披露个人信息。worker 模式也要求显式 `--send`；此开关不能替代用户在具体发送前对目标和内容的审查。

准备阶段应输出 `status: prepared` 或等价本地校验结果而非 `sent`；若目标窗口、内容比对或消息定位不唯一则失败关闭。仅在充分检查后通过可见命令添加 `--send`。超时/提交后状态 `unknown`、报告 `sent: null` 或收据不明时，绝不可自动重试，以免重复发送；先核对实际微信群记录与本地 receipt。不要通过删状态、删收据或绕过 hash 来触发重发。自动日报入口的发送状态机与手动发送不同，先参考 `OPERATIONS.md`，不要在没有明确用户批准时把可能发送的任务设为无人值守。

## 操作员安全复核清单

1. 目标账号、群 ID/名称、时间范围和图像范围由授权人员明确确定；配置没有使用示例替代值。
2. 源数据只读且快照配对，密钥按每库 salt 验证；HMAC/SQLite/WAL/媒体校验失败就停止。
3. 输出目录不公开且权限最小；日志与状态仅含必要计数，不包含 key、passphrase 或消息正文。
4. 镜像、依赖、端口、挂载、Docker 网络和实际运行 UID 符合审阅；keyscan 与常规 worker 权限未混淆。
5. 每份报告、OCR/视觉结果和媒体都保留来源及质量；缺失/不确定项不会伪装为事实。
6. 外部模型、网页访问、站点发布、图片代理和发送是独立披露/副作用，逐项经过授权；未经确认不执行。
7. 归档/清理/升级前备份内容经过加密且不包含多余秘密，保留 no-resend 状态与回滚所需材料。
